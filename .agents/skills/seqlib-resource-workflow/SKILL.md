# 序列库资源维护与 AI 无损规范化 Harness

本技能定义了序列库资源的入库规则与 **AI 改稿专用 Harness（探针诊断 → AI 结合上下文修改 → 结构与无损双门禁校验 → 疑义人工签审）**。

> **核心定位铁律**：一切文本规范化与合并修改均由 **AI 阅读上下文语义后执行**，**严禁编写批量正则替换脚本硬改资源文本**；脚本工具仅作为只读雷达与防幻觉守门员（Harness）。

---

## 1. 目录边界与零篡改红线

1. **默认入库目标**：用户要求“更新资源 / 正式入库 / 规范化资源”时，默认操作正式 `序列库/` 对应目录；仅当用户明确指定放入体验服/新过审暂存区时才写入 `序列库/新过审序列/`。
2. **荣誉室只读保护**：`荣誉室/` 默认只读。历史下架资源“全面重置回归”时，在正式 `序列库/` 对应分类末尾按最大编号 + 1 新增，**不移动、不删除 `荣誉室/` 旧文件**。
3. **规则与数值 100% 零篡改**：
   - 严禁改变任何数值、百分比、骰子表达式、冷却、持续、距离、消耗、判定方式与规则书标签（如 `【异常状态】`、`【光环效果】`）。
   - 历史老稿若原本没有制作人或审核人署名，**有啥留啥、缺失项直接留空省略**，严禁编造人名，严禁写“未知/待复核”，也不触发人工复核。
   - 存量老稿首部无日期（或只有 `312` 月日无年份）的旧改动说明、以及首行拆下的 `（修改版，全改）` 等历史尾注，统一写成 **`【历史更新：...】`** 排在有明确日期的 `【YY.M.D：...】` 记录**之前**，严禁伪造年份，也不进人工复核。
   - 只有真正涉及底层规则语义的变更（如升格为 `[使用要求]：`、跨字段搬移效果与简介）或段落归属不明时，才导出人工签审单。

## 2. AI 规范化 Harness 四步闭环（必跑流程）

对任何单篇或成批资源执行规范化时，AI 必须严格走完以下 4 步：

### 第 1 步：运行只读探针定位病灶（`lint_resources.py`）
```bash
python3 .agents/skills/seqlib-resource-workflow/scripts/lint_resources.py <目标文件或目录> --strict --summary
```
探针会精准标出：漏左括号吞卡（`BROKEN_CARD_LEFT_BRACKET`）、半全角括号混搭（`MIXED_BRACKET_FIELD`）、卡前漂移属性（`PRE_CARD_FLOATING_FIELD`）、卡顶叠层或解锁条件（`CARD_TOP_UNLOCK_OR_SCOPE_RULE` / `UNPREFIXED_MOD_NOTE`）、人员与日志混排、方括号作者、中文日期裸日志、被前卡吞并的公共词条（`POSSIBLE_SWALLOWED_GLOSSARY`）等行号。

### 第 2 步：AI 结合上下文语义无损改稿
阅读探针指出的上下文与 [references/normalization-cases.md](./references/normalization-cases.md) 中的真实正反例，按《资源标准模板.txt》执行修改：
- **首部三段式**：第 1 行严格等于文件名去 `.txt`（后空一行）→ 中文圆括号人员块（存量缺制作人/审核人直接省略）→ 空一行 → 更新日志块（无日期旧记录写成 `【历史更新：...】` 置顶，后接升序排列的 `【YY.M.D：说明】`）。
- **`[XX名称]` 泛匹配成卡**：普通技能/法术/战技写 `[能力名称]：`；称号、道具、能量池、模块、义体、符文、单位、商品、奖励、职阶、天赋、仪式、任务等专用实体**保留各自 `[XX名称]：`**，禁止强改成 `[能力名称]`。
- **卡顶 `【...】` 语义四分法（严禁乱塞进 `[使用要求]`！）**：
  1. **版本改动说明**（如 `【判定加值增加，冷却降低】`）→ 紧贴 `[XX名称]` 正上方写成 `【能力修改：...】`；
  2. **非改动的升级来源 / 特殊备注**（如 `【该义体由基础歧路司义眼升级而来】`）→ 紧贴 `[XX名称]` 正上方写成 `【说明：该义体由基础歧路司义眼升级而来】`（**严禁写成 `[使用要求]`**，因宏观界域底层规则中 `使用要求 = 购买要求` 硬门槛！）；
  3. **极其明确的硬性兑换/携带门槛**（如 `【该技能需要至少10轮回和以MVP身份通过……】`）→ 方可改为卡内 `[使用要求]：...`，且此操作属于**语义字段升格**，`verify_lossless.py` 会自动挂黄牌并生成人工签审单；
  4. **作用于整节多张卡的公共限制**（如 `【备注：以下特殊技能仅能够在你满足...】`）→ 留在小节标题下方作导语，并与第一张卡空一行。
- **公共建筑商品成卡**：对 [001】宏观界域酒馆.txt](file:///Users/lanstard/Documents/macro-realm-seqlib/序列库/公共建筑/001】宏观界域酒馆.txt) 这类结构清晰的自由商品清单（`名称 + 价格： + 效果：`），顺手规范为 `[商品名称]：` + `[兑换价格]：` + `[商品效果]：` 卡片（分组限购转为小节头或 `【说明：...】`）。
- **漂移字段与别名归正**：紧贴 `[XX名称]` 正上方的 `[技艺条件]` / `[技艺难度]` 移入所属卡片内并统一为 `[技艺规则]：`；`[初级能力效果]`～`[终极能力效果]` 统一为 `[初级效果]`～`[终极效果]`；删除无内容的空可选字段。
- **本卡衍生词条与行首 `【XXX】：` 清零铁律**：
  - 前端解析器会将一切行首 `【XXX】：` 识别为结构字段！因此：
    1. 小节标题误带冒号或引言（如 `【职业技能】：`、`【神通】：炼就长生...`）→ 去掉冒号恢复为独立小节头 `【职业技能】` / `【神通】`（引言拆至下一行）；
    2. 本卡衍生的状态/buff 解释（如 `菌主` 的 `【子实体】：buff...`）→ **严禁单开 `【说明】` 大章节**，统一收进所属卡片的 `[补充说明]：` 内，并将行首自定义名改为直角引号 **`「子实体」：...`**；卡内 `【效果1】：` 统一改为纯文本 `效果1：`。
- **全文件空行与字段换行严格管理（6 条硬指标）**：
  1. 全文禁止前导空行，禁止任何连续 `>= 2` 个空行（块间最多保留 1 个空行）；
  2. `[字段名]：` 冒号后必须同行紧跟首条内容（如 `[能力效果]：效果1：...`、`[补充说明]：「子实体」：...`），严禁首行留空换行（避免网页两列网格首行错位留白）；
  3. 卡片内部（字段之间、多条子分项如 `效果1/效果2`、`「子实体」/「感染」`、`劈棍法/立棍法` 之间）一律用单换行连续书写，**严禁夹杂空行**（避免前端 `adaptive.ts` 遇到空行将后续内容拆出字段框）；
  4. 相邻卡片之间必须保留 1 个空行（单卡正上方紧贴的 `【能力修改：...】` / `【说明：...】` 与 `[XX名称]：` 之间不留空行）；
  5. 独立 `【小节标题】` 上方与下方均必须各保留 1 个空行；
  6. 首部三大块（标题 / 连续人员块 / 连续更新日志块）之间各保留 1 个空行，人员块内部与日志块内部不留空行。
- **首部日志防吞背景**：若首部存在 `【YY.M.D：...】` 或 `【历史更新：...】` 日志，且下方紧接多行无小节头的背景介绍/成长树散文，必须在日志块后补一行 `【特质说明】` / `【职业说明】` / `【技能表说明】`（或 `【背景】`）小节头，防止阅读器将最后一条更新日志当成统领整段背景的大章节标题。
- **0 卡老表重构与重影清理**：
  - 非公共建筑资源若因 `〖...〗` 空心括号、漏冒号、裸写字段或 `1.~19.` 列表体裁（如 `058】帝皇的十九道手术`）导致 0 卡识别，统一无损重构为标准 `[能力名称]：` / `[称号名称]：` 卡片；
  - 多人合集大表（如 `006】技艺技能表`）正文中间出现的单卡 `制作人：xxx`，保留在单卡上方写成 `【说明：制作人：xxx】`，**严禁抽到文件第 1 行冒充全表作者**；
  - 卡片正上方残留的、与卡内效果 100% 重复的旧版重影摘要（如 `018】役亡师`）允许清理，`verify_lossless.py` 会自动识别为去重操作并挂黄牌生成签审单。

### 第 3 步：跑通双重只读门禁自检（未全绿禁止收工）
AI 改完文件后，**必须连续跑通以下两条命令**：
```bash
# 门禁 1：结构语法体检（要求 ERROR = 0，且可消除的格式 WARN 清零）
python3 .agents/skills/seqlib-resource-workflow/scripts/lint_resources.py <目标文件> --strict

# 门禁 2：AI 改稿无损对账 + 字段语义看门狗（发现升格为 [使用要求] 等语义变更自动挂黄牌生成签审单）
python3 .agents/skills/seqlib-resource-workflow/scripts/verify_lossless.py <目标文件> --auto-review-on-semantic
```
- 若 `verify_lossless.py` 报 `FAIL`（例如漏抄了半句话、改错了数字或同音字、删掉了首行尾注），AI 必须立即对照原稿修回，直到 `PASS`。

### 第 4 步：存疑灰区导出人工签审单（`--emit-review`）
对存在规则语义歧义、首行残留投稿附注无法无损消化、或需制作人拍板的档案，生成人工签审任务 JSON（对接在线站 `/normalize-review`）：
```bash
python3 .agents/skills/seqlib-resource-workflow/scripts/verify_lossless.py <目标文件> \
  --emit-review --note "说明需要人工确认的具体位置与原因"
```
