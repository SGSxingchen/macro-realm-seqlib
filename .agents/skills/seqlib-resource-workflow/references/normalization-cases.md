# 序列库 AI 无损规范化：真实疑难抽例与上下文判别手册（v3）

本参考手册收录了从正式 `序列库/` 真实档案中抽检出的全部典型深水区边界。
**核心原则：所有文本修改均由 AI 阅读上下文语义完成，严禁用死板正则脚本硬替；每次改完必须跑通 `lint_resources.py --strict` 与 `verify_lossless.py` 双重 Harness 门禁。**

## 案例 1：卡片正上方叠了多层 `【...】` 与 `[使用要求]` 红线

### 场景 A：修改备注 + 升级来源说明混排（源自 `015】义体改装《赛博朋克2077》.txt`）
**修改前（原文）：**
```text
【判定加值增加，高亮效果冷却降低】
【该义体由基础歧路司义眼升级而来】
[义体名称]：歧路司义眼“千里目”（A级）（占用6点战力）
[能力简介]：歧路司义眼的升级型号，由高端组件制造，其加速扫描算法能保证顾客满意度达到100%。
```
**AI 正确改法：**
- 第 1 行描述本次版本改动方向 → 补前缀写成 `【能力修改：判定加值增加，高亮效果冷却降低】`。
- 第 2 行是升级来源说明 —— **严禁改成 `[使用要求]：`**（在宏观界域底层规则中，`使用要求 = 购买要求` 硬门槛，乱改会篡改规则结算！）→ 补前缀写成 `【说明：该义体由基础歧路司义眼升级而来】`。
- `[义体名称]` 属于专用实体卡头，**100% 原样保留，禁止改成 `[能力名称]`**。

```text
【能力修改：判定加值增加，高亮效果冷却降低】
【说明：该义体由基础歧路司义眼升级而来】
[义体名称]：歧路司义眼“千里目”（A级）（占用6点战力）
[能力简介]：歧路司义眼的升级型号，由高端组件制造，其加速扫描算法能保证顾客满意度达到100%。
```

### 场景 B：多人合集表正文中间的单卡独立制作人（源自 `006】技艺技能表.txt` L717）
**修改前（原文）：**
```text
制作人：姜雷
[能力名称]：某单项投稿技艺
```
**AI 正确改法：**
- 切勿将该制作人上移至文件第 1 行冒充整张合集表作者！
- 紧贴该卡正上方写成 `【说明：制作人：姜雷】`。

## 案例 2：半全角混搭括号 + 卡片衍生状态词条 + 首部日志防吞背景（源自 `081】菌主.txt`）

**修改前（原文）：**
```text
081】菌主
[异化特质]
［制作人:闲狐狸］
2025年11月14日更新：S级技能蘑菇的联动效果新增对蚊子基因的打折折扣
E级：解锁基础性能“真菌”……
……
[能力名称]：真菌
[能力效果］：
效果1：身为真菌的主人……友方单位在【菌丝体】上【行走】【站定】时获得一个【子实体】buff……
【效果2】：在菌丝体上……
[释放类型]：被动/主动

【子实体】：buff ，等级等同于你的特质等级……

【感染】：物理/肉体类debuff ，等级等同于你的特质等级……
```
**AI 正确改法（v3 铁律）：**
1. **首部人员紧贴标题空行后**（避免 `[异化特质]` 挡在前面阻断阅读器作者徽章提取），日期日志下方**必须补一行 `【特质说明】`**，防止阅读器把最后一条更新日志渲染成统领背景与成长树的大章节 `<h2>` 标题！
2. **禁止新建顶层 `【说明】` 大章节，禁止残留任何行首 `【XXX】：`**（前端 `adaptive.ts` 会将一切行首 `【XXX】：` 拆成孤儿字段框）：
   - 将卡片衍生的内部状态定义收归所属卡片的 `[补充说明]：` 字段内；
   - 行首自定义词条名改为直角引号 `「子实体」：`、`「感染」：`；
   - 同卡并列子效果统一为无括号 `效果1：`、`效果2：`。

```text
081】菌主

（制作人：闲狐狸）

【25.11.14：S级技能蘑菇的联动效果新增对蚊子基因的打折折扣】

【特质说明】

[异化特质]
【E】级：解锁基础性能“真菌”……
……
[能力名称]：真菌
[能力效果]：效果1：身为真菌的主人……
效果2：在菌丝体上……
[释放类型]：被动/主动
[补充说明]：「子实体」：buff ，等级等同于你的特质等级……
「感染」：物理/肉体类debuff ，等级等同于你的特质等级……
```

## 案例 3：0 卡远古档案与编号列表成卡重构（`009】血莲化生`、`012】龙吼`、`058】帝皇的十九道手术`）

1. **空心括号/无冒号/全裸写老表**：将 `〖能力名称〗`、`【能力名称】xxx`、裸写 `能力名称：xxx` 统一重构为标准 `[能力名称]：xxx`（称号则用 `[称号名称]：`）；原稿中的 `【日期待复核：...】` 或无年份 `更新：...` 统一转为 `【历史更新：...】` 排在带日期日志之前。
2. **1.~19. 编号器官/改造列表（如 `058】帝皇的十九道手术《战锤》.txt`）**：
   - 将 `1.第二心脏（B/A）` 重构为 `[能力名称]：1.第二心脏（B/A）`（保留 `1.~19.` 植入顺序编号与原名，零丢字零改数）；
   - 规则效果归入 `[能力效果]：`，下方包裹在 `【...】` 内的器官设定背景归入同卡 `[能力简介]：`（跨字段归类将由 `verify_lossless.py` 自动挂黄牌供人工一眼签审确认）。

## 案例 4：清理卡顶 100% 重复的旧版残影（源自 `018】役亡师【法术】《英雄无敌》.txt`）

**修改前（原文）：**
```text
【死非终结】：将一名刚死去不久的单位复活……（与下方能力效果一字不差）
[技能名称]：死非终结
[能力效果]：将一名刚死去不久的单位复活……
```
**AI 正确改法：**
- 允许直接清理上方 100% 重复的旧版残影行（以及无内容的空壳重影头 `【牺牲】：`），并将 `[技能名称]：` 统一为 `[能力名称]：`。
- 改完后运行 `verify_lossless.py --auto-review-on-semantic`：对账器会自动核验该段文字与数值在改后仍完整保留（`count >= 2 -> >= 1`），放行红牌并自动生成黄牌去重签审单（`dedup_changes`）。

## 案例 5：小节标题尾随冒号吞正文（源自 `063】天命人《黑神话：悟空》.txt`）

**修改前（原文）：**
```text
【神通】：炼就神通需要根器支撑，每个等级解锁一项……
```
**问题根因：** 带冒号的 `【神通】：` 会被前端当成上一张卡片的字段吞入卡底！
**AI 正确改法：** 剥离小节标题冒号，将导语移至下一行独立成段：
```text
【神通】

炼就神通需要根器支撑，每个等级解锁一项……
```
