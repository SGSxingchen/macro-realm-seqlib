# V6.6 发布与打包流程

本文记录宏观界域强化序列库 V6.6 的固定发布流程。执行发布时以本文、`build_config.json` 和 GitHub Actions 工作流为准，避免旧版本说明、旧下架名单或未校验的产物混入发布包。

## 一、版本口径

- 版本号：`V6.6`
- Git 标签：`v6.6`
- 差异基线：`v6.5.4`
- 正式发布时间：2026-07-11
- 更新奖励：10000积分 + 300碎片
- 奖励领取范围：全体可领取，持续至下一次序列库更新
- 更新折扣：本次更新涉及的全部资源八折
- 退款口径：本次实质改动资源可整项退款，仅修正描述的资源不计入
- 折扣、退款截止日期：2026-08-15
- 本版正式执行第十、十一批下架：名单共48条，重复2条，实际下架46项。
- 替换归档：`第一天灾-虫群`替换`虫母`，`虫母`旧版移入荣誉室。

## 二、V6.6 根目录打包白名单

V6.6 只收录以下根目录文件：

1. `6.6序列库编者注.txt`
2. `V6.6序列库更新日志.txt`
3. `第十批下架名单.txt`
4. `第十一批下架名单.txt`
5. `资源标准模板.txt`

白名单在 `build_config.json` 的 `root_files.6.6` 中维护。V6.5 的编者注、更新日志及第七至九批下架名单不得进入 V6.6 发布包。

## 三、发布前内容检查

1. 确认所有正式下架资源已经从 `序列库/` 移入 `荣誉室/`。
2. 执行编号检查，结果应显示没有待重排项目：

   ```bash
   python3 tools/renumber_resources.py
   ```

3. 检查改动和空白错误：

   ```bash
   git status --short
   git diff --check
   git diff --stat
   ```

4. 核对更新日志中的发布日期、奖励、退款截止日期、资源数量和下架数量。
5. 对本次所有资源更新日志做一次人工语义复核，重点检查：
   - 人员信息在前、更新日志在后；
   - 日志从早到晚排列；
   - 同一天日志尽可能合并；
   - 日志连续排列，不夹杂多余空行；
   - 冷却时间与“每若干回合一次”等频率描述没有被互相替换。

## 四、本地自动校验

运行构建配置、编号工具和 Wiki 工作流相关测试：

```bash
python3 -m pytest -q tests/test_build_chm.py
python3 -m unittest -q \
  tests.test_renumber_resources \
  tests.test_session_stats \
  tests.test_wiki_sync_workflow
```

只构建 ZIP 进行本地打包验证：

```bash
rm -rf /tmp/macro-realm-v66-release-check
python3 build_chm.py \
  --version v6.6 \
  --skip-chm \
  --source-dir . \
  --output-dir /tmp/macro-realm-v66-release-check
unzip -l '/tmp/macro-realm-v66-release-check/宏观界域强化序列库V6.6.zip'
```

ZIP 必须包含第二节列出的5个根目录文件，并排除 V6.5 根文件及第七至九批下架名单。

macOS 本地不负责最终 CHM 校验。正式 CHM 由 Windows GitHub Actions 使用仓库内置 `hhc.exe` 构建；工作流会在产物缺失或为空时失败。

## 五、Wiki 发布前试运行

推送 `v6.6` 标签会同时触发真实 Wiki 增量同步，因此打标签前必须先以 `v6.5.4` 为基线执行 dry-run。

推荐在 GitHub Actions 的“Wiki 同步”工作流中手动运行：

- 同步模式：`dry-run`
- 同步范围：`custom-ref`
- 起始 tag/commit：`v6.5.4`
- 跳过荣誉室：`false`
- 过滤目录：留空

确认 dry-run 的新增、更新、移动和删除范围符合预期后，才进入正式标签发布。

## 六、提交与发布

本次发布涉及构建配置、工作流和根目录说明文件，必须人工核对暂存清单，不能只依赖网页发布接口的文件白名单。

只有在确认当前工作树的全部改动都属于 V6.6 时才使用 `git add -A`；若存在并行任务或无关改动，应改为按文件和目录精确暂存。

```bash
git add -A
git status --short
git diff --cached --check
git diff --cached --stat
git commit -m "发布 V6.6 序列库更新"
git tag -a v6.6 -m "发布 V6.6 序列库更新"
git push origin main
git push origin v6.6
```

只精确推送 `v6.6`，不要使用 `git push --tags`，避免把无关本地标签一并推送。

## 七、发布后验证

1. 确认“发布序列库”工作流成功。
2. 确认 Release 中同时存在非空的 V6.6 CHM 与 ZIP。
3. 下载 ZIP，复核根目录白名单和随机抽查资源正文。
4. 确认“Wiki 同步”工作流以 `v6.5.4 → v6.6` 为范围成功执行。
5. 检查在线查询网站与 Wiki 中的下架资源是否已进入荣誉室范围。

## 八、发布公告口径

1. 本次更新涉及的全部资源统一八折，折扣截止至2026-08-15。
2. 本次实质改动资源可整项退款，退款截止至2026-08-15；仅修正描述的资源不计入退款范围。
3. 更新奖励为10000积分 + 300碎片，全体可领取，持续至下一次序列库更新。
4. GitHub Release 正文直接使用 `V6.6序列库更新日志.txt`。
5. 本版统一八折口径优先于资源首部历史记录中的“不打折”“无折扣”等旧备注。
