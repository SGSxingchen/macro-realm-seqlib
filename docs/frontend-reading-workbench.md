# 阅读工作台补充：收起边栏、多档案与历史对照

本次继续更新 PR #1，不修改任何资源正文、资源路径、后端接口、生产配置或发布流程。

## 布局与多档案

索引、结果可以分别收起，顶端布局栏始终保留恢复按钮。独立开关存 localStorage；专注阅读临时隐藏两栏，退出恢复开关原值。进入并排/历史对照会临时让出空间，仍可手动展开结果继续找资源。Ctrl/⌘ K 在结果隐藏时先恢复结果，再聚焦搜索。手机仍采用结果/阅读分屏，不强塞三栏。

打开的资源保留为标签，以完整路径去重；关闭活动标签后切换到相邻标签，关闭非活动标签不切换正文。最近 30 个标签的路径/标题存入 sessionStorage，可在同一浏览器标签页刷新后恢复；不保存全文或任何凭证。阅读方式、文内查找和滚动位置保留于当前页面会话。刷新后不声称恢复滚动位置。

并排对照固定右侧参照，左侧主档案可通过标签来回切换；两侧独立滚动，不强制对齐不同技能模板。可更换参照、交换两侧、退出并排。主/参照的状态与锚点隔离，避免两个资源含同名能力时的 DOM ID 冲突。窄屏改成主/参照窗格切换，保留双方阅读位置，而不是把正文压成两条窄列。

## 历史对照：这一轮能做什么

复用已存在的只读 `/api/git/changes` 和 `/api/git/change-detail/{path}`，请求均设置 `public_only=true`。

用户输入标签/ref（留空使用后端默认基线），比较一个旧版本文件与服务器当前资源。可从 Git 变更返回的改名项中选候选旧路径，也可手填已知的旧路径。候选必须由用户点击确认才开始比较；不会后台默认为同一资源。界面持续显示基准版本、旧路径、当前路径与工作区标记。

安全边界：
- Git 相似度、同路径、同名称都不是资源身份的证明。编号重排可能复用旧路径，必须核对旧内容。
- 旧文件不存在时不渲染“全量新增”差异；两侧均存在才展示行差异。
- 接口 `truncated` 与省略上下文 `gap` 明确显示，不冒充完整差异。
- 更换基线或路径会取消旧请求、清除旧结果，避免串版。
- 显示文本增删，不将文本差异解读为加强、削弱或规则语义结论。

尚未实现：任意两个旧版本互比、完整跨多次改名的历史链、持久资源身份映射、自动语义对齐。没有添加数据库、资源 ID、改名追踪表或全库扫描新接口。

## 为什么改名并非完全无解

Git 的 `log --follow` 可以继续跟踪单个文件的改名历史，`diff --find-renames` 使用内容相似度判断；全面重写、拆分/合并、同名资源、编号重用或不完整 Git 历史都需要谨慎处理。当前接口使用的是基线到当前的差异，不等同于实现了完整 `--follow` 历史链。

下一阶段若需要完整版本时间线，应单独设计只读历史 API：限定可见版本、解析 NUL 分隔路径、保留每次提交的旧路径、明确候选来源与不确定性、提供人工映射确认，再测试连续重命名、重排编号、同名、多分支与重置回归。是否引入稳定 ID/人工映射应另行确认，不在本次违反原项目的路径事实源约定。

依据：
- https://git-scm.com/docs/git-log （`--follow`）
- https://git-scm.com/docs/git-diff （`-M` / `--find-renames`）
